# Methodology and design choices

The assignment requires evidence retrieval across documents, not direct whole-PDF prompting. Indexing and generation are therefore separate phases. PyMuPDF preserves a traceable page unit; text cleanup retains numeric punctuation, dates and paragraph breaks. Repeated headers are retained because heuristics could erase meaningful headings. The sample reports are original and deliberately simple enough to inspect manually.

Recursive character splitting tries paragraph, line, sentence and word boundaries before character fallback. Defaults are 1,000 characters and up to 200 characters overlap. Actual overlap can be shorter at natural boundaries. Splitting per page makes citations unambiguous but may separate a paragraph spanning pages. These defaults are engineering starting points, not experimentally optimal settings.

All-MiniLM-L6-v2 provides lightweight CPU semantic embeddings. Inputs longer than the model's token limit are divided into windows; normalized window vectors are averaged and then normalized by the store. This preserves tail participation but may dilute distinct topics. The same encoder and pooling are used for queries and documents. FAISS exact inner-product search is straightforward and appropriate for the bounded local collection. No ANN tuning is needed for the sample scale.

Top-k=5 and cosine cutoff=0.30 bound the context. The threshold has not been calibrated on a broad external dataset. Increasing k can improve multi-document recall but introduce distracting evidence. A weak relevant match does not imply answerability. The LLM must additionally decide whether the retrieved evidence answers the question.

Gemini receives a separate system instruction and JSON data. Clear standalone questions pass directly to retrieval. A reference detector routes pronouns, demonstratives and continuations such as “What about 2024?” through bounded-history reformulation; unresolved references request clarification. This change followed observed over-clarification in the first live run. The detector is heuristic and can miss subtler elliptical questions. Generation uses temperature 0.1 and a Pydantic JSON schema. Each claim has source-ID/quote pairs. The application checks actual quote membership and derives metadata itself. Conflict handling is requested explicitly in the system prompt. Live results and the preserved first-run failures are reported separately from deterministic tests.

Evaluation gold labels identify source/page pairs before retrieval. Recall@K is the fraction of expected pages present, hit rate is any expected page present, and reciprocal rank is the inverse rank of the first relevant chunk. Multiple chunks from a page do not inflate recall. Cases without gold pages are excluded from retrieval denominators. Offline follow-ups use gold reformulations; this isolates retrieval from query rewriting. Live mode executes histories instead and saves answers for human scoring. See the evaluation report for rubrics and actual results.
